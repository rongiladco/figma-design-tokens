# Starting from scratch

No reference material means the interview in SKILL.md §2 has to do more work — it's the only source of direction. Add these before moving to §3:

- **Three adjectives** that describe how this should feel (e.g. "confident, warm, minimal" vs. "playful, bold, energetic"). This is the single highest-leverage question — it's what turns a color-picker exercise into a system with a point of view, and it's what you'll come back to if a later choice feels arbitrary.
- **Industry / product category**, if not already obvious from context — a fintech dashboard and a kids' education app want very different defaults even with the same three adjectives.
- **Any fixed anchor**, even a small one — a favorite color, a font they've always liked, a competitor's system they admire (or want to avoid looking like). People rarely want a truly blank slate; surface whatever partial preference exists rather than assuming there's none.
- **Light or dark as the "home" mode**, if dark mode is in scope — one of them is still the primary design surface even if both exist.

From there, propose one direction (a primary hue + a font pairing + the default semantic role set from `references/token-schema.md`) rather than presenting an open-ended menu of options — it's much easier for someone to react to "here's a direction, what would you change" than to invent a whole system from nothing themselves. Then iterate per SKILL.md §5.
